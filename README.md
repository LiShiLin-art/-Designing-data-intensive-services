# -Designing-data-intensive-services
курс МПГУ

**Общая трудоёмкость:** 144 академических часа (4 зачётные единицы): 32 ч лекций, 56 ч практических занятий, 56 ч самостоятельной работы.

**Сквозной проект:** микросервисное приложение «Интернет-магазин с аналитикой в реальном времени» на Python (FastAPI). Проект выполняется индивидуально или в парах (2 человека). Каждый модуль добавляет в систему новый компонент.

**Инфраструктура:** все компоненты разворачиваются локально на машинах студентов через Docker Compose и minikube.

---
## Модуль 1. Введение в высоконагруженные системы и метрики (6 ч)

**Теоретическая часть (4 ч)**

- Что такое высоконагруженная система: throughput, latency, error rate, saturation.
- SLA, SLO, SLI. Back-of-the-envelope estimation.
- CAP-теорема и PACELC. Компромиссы согласованности и доступности.
- Горизонтальное и вертикальное масштабирование. Закон Амдала.
- Особенности Python под нагрузкой: GIL, asyncio, выбор ASGI-сервера.

**Практическая работа (2 ч)**

Нагрузочное тестирование базового HTTP-сервиса на FastAPI с помощью Locust. Снятие метрик latency/throughput, построение графиков, выявление узкого места.

**Литература**

- Базовая: Клеппман М. «Высоконагруженные приложения» — гл. 1–2.
- Углублённая: Gorelick M., Ozsvald I. «High Performance Python» (3rd ed.) — гл. 1–2.

## Модуль 2. Сеть, протоколы и балансировка нагрузки (8 ч)

**Теоретическая часть (4 ч)**

- HTTP/1.1, HTTP/2, HTTP/3. REST vs gRPC.
- DNS, Service Discovery, API Gateway.
- Алгоритмы балансировки: round-robin, least connections, consistent hashing.
- L4 vs L7 балансировщики: Nginx, HAProxy.

**Практическая работа (4 ч)**

Развёртывание Nginx как reverse proxy перед двумя экземплярами FastAPI-сервиса. Настройка health-check и балансировки. Проверка отказоустойчивости при остановке одного инстанса. Настройка Gunicorn/Uvicorn с несколькими worker-процессами.

**Литература**

- Базовая: материалы курса System Design — модуль 02.[здесь](https://github.com/cranes-mentoring/system-design#1)
- Углублённая: документация Nginx, курс «Высоконагруженный Python-бэкенд» (IBS Training) — раздел «Серверы приложений и Worker-модели».

## Модуль 3. Базы данных под нагрузкой (14 ч)

**Теоретическая часть (6 ч)**

- Индексы (B-tree, GIN, GiST), планы запросов. EXPLAIN ANALYZE.
- Транзакции, уровни изоляции, MVCC.
- Репликация: master-slave, синхронная/асинхронная.
- Шардирование и партиционирование.
- Асинхронная работа с БД через SQLAlchemy 2.0 и asyncpg.

**Практическая работа (8 ч)**

Добавление PostgreSQL в проект. Создание схемы для пользователей, товаров и заказов. Настройка read-replica. Написание запроса с шардированием по `user_id`. Сравнение производительности до и после индексации. Настройка connection pooling.

**Литература**

- Базовая: Клеппман М. «Высоконагруженные приложения» — гл. 5–6.
- Углублённая: документация SQLAlchemy 2.0 (async), репозиторий Basic-CRUD-Service-Python (пример слоистой архитектуры).

## Модуль 4. Кеширование и CDN (8 ч)

**Теоретическая часть (4 ч)**

- Уровни кеширования: клиент, CDN, application, database.
- Стратегии: cache-aside, write-through, write-behind.
- Инвалидация кеша. Cache stampede (dogpile effect) и его предотвращение.
- Redis: сценарии использования, TTL, eviction policies.

**Практическая работа (4 ч)**

Внедрение Redis (через `redis.asyncio`) для кеширования каталога товаров. Реализация cache-aside. Нагрузочное тестирование с холодным и тёплым кешем. Настройка TTL и инвалидации при обновлении товара.

**Литература**

- Базовая: материалы курса System Design — модуль 05.
- Углублённая: документация Redis, руководство «Using Redis with FastAPI».

## Модуль 5. Асинхронность, очереди и событийно-ориентированная архитектура (16 ч)

**Теоретическая часть (8 ч)**

- Проблемы синхронных вызовов: каскадные отказы, latency amplification.
- Message brokers: RabbitMQ, Kafka. Модели очередей и топиков.
- Гарантии доставки: at-most-once, at-least-once, exactly-once.
- Event-Driven Architecture. Паттерны: pub/sub, event sourcing, CQRS.
- Stream processing: Kafka Streams, consumer groups, offsets.
- Asyncio под нагрузкой: TaskGroup, structured concurrency, отмена и таймауты.

**Практическая работа (8 ч)**

Добавление Kafka в проект. Асинхронная обработка заказов: событие `order.created` → сервис уведомлений и сервис аналитики. Реализация идемпотентного consumer на Python (`aiokafka`). Мониторинг лага consumer group. Обработка длительных задач через Celery + Redis.

**Литература**

- Базовая: материалы курса System Design — модули 06–07.
- Углублённая: Sharma G. «Event-Driven Architecture with Python and Apache Kafka»; курс по асинхронному Python 2026 (разделы TaskGroup, structured concurrency).

## Модуль 6. Микросервисная архитектура и декомпозиция (16 ч)

**Теоретическая часть (8 ч)**

- Монолит vs SOA vs микросервисы. Критерии декомпозиции по бизнес-способностям.
- Domain-Driven Design: bounded context, ubiquitous language.
- API design: REST, gRPC, контракты, версионирование.
- Паттерны: Saga, Outbox, Transactional Outbox, API Gateway, BFF.
- Service mesh: концепция sidecar-прокси.

**Практическая работа (8 ч)**

Декомпозиция монолитного FastAPI-приложения на три сервиса: `users`, `catalog`, `orders`. Выделение общего API Gateway. Реализация межсервисного взаимодействия через gRPC (библиотека `grpcio`). Внедрение паттерна Saga для оформления заказа с распределённой транзакцией (компенсирующие транзакции).

**Литература**

- Базовая: Баланов А. Н. «Построение микросервисной архитектуры…» — главы 1–4.
- Углублённая: Poulos J. M. «The Ultimate High-performance Microservices with Python & FastAPI» (2025) — главы о Saga и Event-Driven Architecture.

## Модуль 7. Наблюдаемость и отказоустойчивость (14 ч)

**Теоретическая часть (6 ч)**

- Три столпа наблюдаемости: логи, метрики, трейсинг.
- Prometheus, Grafana, OpenTelemetry. Структурированное логирование.
- Circuit breaker, retry с exponential backoff, rate limiting, load shedding.
- Chaos engineering: принципы и инструменты.

**Практическая работа (8 ч)**

Интеграция OpenTelemetry в микросервисы (автоматическая инструментация FastAPI + ручные спаны). Сбор метрик в Prometheus, дашборды Grafana. Настройка circuit breaker (`pybreaker`) для вызовов между сервисами. Проведение chaos-эксперимента: отключение одного сервиса и проверка деградации.

**Литература**

- Базовая: материалы курса System Design — модули 09–10.
- Углублённая: документация OpenTelemetry Python, руководство Pluralsight «Implement OpenTelemetry for Python Observability».

## Модуль 8. Контейнеризация, оркестрация и CI/CD (18 ч)

**Теоретическая часть (8 ч)**

- Docker: образы, слои, multi-stage builds для Python-приложений.
- Kubernetes: Pod, Deployment, Service, Ingress, HPA.
- minikube: запуск локального одноузлового кластера, аддоны, `minikube service`.
- CI/CD: GitHub Actions. Стратегии деплоя: blue-green, canary.
- Helm: чарты для управления манифестами.

**Практическая работа (10 ч)**

Контейнеризация всех сервисов. Написание `Dockerfile` (multi-stage) и `docker-compose.yml` для локального запуска. Деплой в minikube. Настройка Horizontal Pod Autoscaler по CPU. Написание Helm-чарта для одного из сервисов. Пайплайн GitHub Actions: сборка, тесты, пуш образа.

**Литература**

- Базовая: официальная документация Docker и Kubernetes; руководство «Hello Minikube».
- Углублённая: лабораторная работа «Deploying FastAPI and PostgreSQL Microservices to Kubernetes using Minikube»; Heck J. «Kubernetes for Developers» — главы о minikube.

## Модуль 10. Итоговая защита проекта (6 ч)

**Формат:** демонстрация работающего микросервисного приложения, развёрнутого в minikube, с нагрузочным тестом (Locust), дашбордами Grafana, отчётом о chaos-эксперименте и Helm-чартами. Проект выполняется индивидуально или в парах (2 человека); в случае парной работы оценивается вклад каждого участника и качество взаимодействия (код-ревью, распределение задач).

**Критерии оценки:** работоспособность системы, качество архитектуры (декомпозиция, Saga), наблюдаемость (метрики, трейсинг), отказоустойчивость (circuit breaker, chaos-эксперимент), качество презентации.
